# 浏览器互动数据回填设计

## 目标

使用项目独立的 Microsoft Edge 持久化会话，为 `data/videos.csv` 中已有视频回填播放量、点赞数、投币数、收藏数和分享数。每次只处理 50 条，并保持单线程、顺序访问和可恢复执行。

## 范围

- 数据源仅为 B 站正常视频详情页，不使用搜索 API、详情 API、Cookie 导出、代理、stealth 或自动登录。
- 读取与更新目标为原始 `data/videos.csv`；不自动运行清洗、HDFS 上传、Spark、挖掘或 QA。
- `videos_cleaned.csv` 由管理员在回填后按既有流程手动重新清洗，避免隐式改变数据处理流程。
- 每次回填最多 50 条；浏览器始终使用 `channel="msedge"` 和项目独立 `browser_data/`。

## 数据与断点

互动字段中的 `0` 可能是真实值，也可能是阶段 B/C 写入的占位值，因此不能仅以“字段是否为 0”判断是否已处理。新增本地回填状态文件，记录已完成 URL，以及失败 URL 的尝试次数和短原因；它不保存 Cookie、账号、完整异常、页面 HTML 或互动数据副本。

每个详情页成功解析后，立即将该视频的五项数值更新到 `videos.csv`，随后写入状态文件。单个页面超时、验证或结构异常时记录失败并继续，新 URL 全部处理后再按失败次数和原始顺序重试，单个 URL 最多尝试 3 次。旧式 HTTP AV 链接仅在本模块内规范化为 HTTPS；课程 season URL 不是普通视频详情页，明确记录为 `unsupported_course_url`。

## 浏览器与错误行为

回填开始前先用真实 Edge 打开一个详情页，并仅根据实际页面确定稳定的互动字段选择器。分享数使用真实页面的 `.video-share-wrap .video-toolbar-item-text`；仅正文课程目录出现“验证码”不能判为验证页。每页等待正常加载，不绕过验证码；连续两个页面出现明确安全验证时触发熔断并报告已回填数量。浏览器启动失败继续 fail fast，页面超时和结构异常保留短失败状态供后续有限重试。

## Web 接入

在现有 `/data` 管理页面增加独立的“互动数据回填”操作，固定显示每批 50 条。仅管理员可调用；使用与浏览器采集相同的非阻塞锁，`try/finally` 必须释放。页面只显示小型摘要：计划数、成功数、跳过数、状态和当前原始数据总量。

## 验证

先写 mock 测试，覆盖详情字段解析、数值转换、真实分享 DOM、验证误判回归、状态文件断点、AV 规范化、重复行更新、失败跳过与有限重试、验证熔断、管理员权限、锁释放和不自动清洗。随后通过 `run_interaction_backfill.py` 顺序完成所有可回填 URL，核对原始 CSV 行数和五项字段覆盖率，并运行完整 pytest。
