# 最终课堂展示界面修复设计

## 目标

在保留现有 Flask、Jinja2、HDFS、数据挖掘和 Spark 业务逻辑的前提下，将登录后的页面调整为适合课堂演示的传统课程管理系统布局，并解决宽表格与长标题在窄内容区中的溢出问题。

参考课堂示例的布局思想，不逐像素复制：左侧深色功能菜单、右侧宽内容区、顶部统一项目标题、白色模块卡片和绿色操作强调。整体保持普通本科课程作业风格，不引入新的前端框架、构建工具或图标依赖。

## 修改范围

主要修改：

- `templates/base.html`
- `templates/data.html`
- `templates/mining.html`
- `templates/visualization.html`
- `static/css/style.css`

仅在统一布局确有需要时，对首页、采集页或知识库模板添加少量 class。不修改采集器、HDFS 路径与交换逻辑、数据挖掘算法、Spark 分析算法、数据库结构和 11 字段合同。

## 全局布局

登录后页面采用两栏结构：

- 左侧约 210px 的深色侧栏，标题为“功能菜单”。
- 菜单顺序为首页、数据查询、管理员数据采集、数据挖掘、Spark 可视化、AI 知识库和退出登录。
- 当前路由对应菜单项使用绿色背景高亮，通过 Jinja2 的当前请求端点判断，不增加 JavaScript 菜单逻辑。
- 右侧为页面容器，顶部居中显示“基于大数据技术的B站视频数据分析与AI知识库”。
- 主内容宽度为 `min(1280px, calc(100% - 48px))`，宽表格和图表可使用完整内容区。
- 登录页不渲染侧栏和业务标题，继续使用居中、窄宽度登录卡片。

在窄屏下，侧栏转为顶部的紧凑菜单区域，主内容保留合理边距；宽表格通过自身横向滚动保持可读性，不把单元格压成竖排。

## 数据查询页

查询条件使用紧凑操作卡片，在桌面端将日期、关键词和查询按钮排列为一行，在窄屏下自然换行。结果放入独立宽卡片，并显示当前查询对应的正式数据总量；总量使用现有分页计算所需的数据长度传入模板，不硬编码 11062。

结果表外包裹 `.table-responsive`。表格使用固定布局和 `colgroup`：BV 号、标题、UP 主、发布时间及五个数字字段分别获得明确宽度。标题允许换行并限制为最多三行，链接保留完整 `title` 提示；BV 号、表头和数字列不换行，数字右对齐。移动端允许表格横向滚动。

分页和搜索参数保持现有行为，不改变查询与 HDFS 读取逻辑。

## 数据挖掘页

日期和分析按钮使用与数据查询页相同的紧凑操作区。算法调用和输入数据完全不变。

- KMeans 使用整齐的四列表格：分组、视频数、平均播放、平均点赞。
- 爆款预测先用四个简单统计块展示阈值、准确率、精确率和召回率。
- 模型仍对全部正式数据训练、计算和预测；模板只渲染 `predictions[:20]`，标题为“预测结果示例”，并说明仅展示前 20 条。
- 预测表示例列宽为 BV 号 20%、标题 60%、预测结果 20%；结果列禁止换行，标题允许最多三行并提供 `title`。
- Apriori 继续展示前项、后项、支持度、置信度和提升度；规则文本可换行，数值列不换行。

## Spark 可视化页

页面继续调用真实 `run_spark_analysis()`，不使用 pandas 结果或静态数据替代。顶部操作区与其他页面一致；成功时四个图表在桌面端使用 2×2 卡片网格，窄屏下改为单列。保留 ECharts 的名称截断和完整 tooltip，柱形强调色调整为与全站一致的绿色。

Spark 失败单独按环境链路调查：核对 Java、Spark、Python、HDFS、项目路径和网关启动信息。优先在纯 ASCII 路径的同一代码版本和同一配置中复测，以区分中文路径 classpath 问题、Codex 受限环境的端口绑定问题和用户真实 Windows 环境问题。除非证据指向生产缺陷，否则不修改 Spark 业务代码。

## 错误处理与可追溯性

现有 HDFS、Spark 和挖掘错误提示保持可见，不使用 CSS 隐藏失败状态。Spark 验证记录完整异常、Java/Spark 版本、解释器、路径和 HDFS 连通性。界面修改不增加吞错或假数据兜底。

## 测试与验收

先补最小失败测试：

- 登录后基础模板包含侧栏菜单和统一标题，登录页不显示业务侧栏。
- 数据页包含响应式表格容器、标题提示和正式数据量。
- 挖掘页只展示前 20 条预测示例，同时通过 mock 证明传入算法的记录仍是完整集合。
- Spark 页面仍包含四个真实图表容器和现有 ECharts 数据入口。

实现后使用日期 `2026-08-14` 在真实浏览器检查 `/data`、`/mining` 和 `/visualization`，保存三张修复后截图。数据页检查九列表格、搜索和分页；挖掘页检查三类结果及长标题；Spark 页只有在真实 Spark 成功后才确认四图成功。

最后运行完整 pytest、Node 测试、Spark 集成测试、`compileall`、`git diff --check` 和禁用项扫描，并核对差异仅落在设计范围内。
